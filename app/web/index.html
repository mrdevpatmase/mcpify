MCPify checks the common MCP paths on your URL. If none respond, it wraps your API in a proxy so it still works as an MCP server.

What kind of links work?

Every category except the last still gets you a link. What matters is whether the tools behind it return real data. Pick any example to try it.

Works fully
Link generated, tools return real data
  • Real MCP servers Detected and connected directly, no proxy needed. Streamable HTTP and SSE are both supported.
  • Public REST APIs Wrapped into MCP tools automatically: call_api, get_info and health_check.
  • APIs hosted under a path For example api.example.com/v1 or example.com/api.
  • APIs with a Bearer token Pass your API key and it is forwarded on every call.
Try it
Works with limits
Link generated, results may be empty
  • Marketing or docs-only sites A proxy is still created, but tool calls return no real data if there is no API behind the site.
  • Auth beyond a Bearer token OAuth flows, custom auth headers and cookie-based login are not supported yet.
  • Slow APIs Calls time out after about 15 seconds.
Try it
Not supported
No link generated, request is refused
  • Private, internal or localhost URLs Blocked for security to prevent SSRF attacks.
  • Unreachable domains There is nothing at the address to connect to.
  • Malformed URLs Refused with a clear error message.
